# z-jellyfin-hub 开发规范

## 工程

Go 1.27 标准库 HTTP，SQLite 使用无 CGO 驱动；Vue 3、TypeScript、Vue Router hash history 与 Vite 构建管理后台并嵌入 Go。前端从物理目录推导前缀，禁止写死 /hub/；管理 hash 不得进入 API/静态资源/订阅链接。页面请求按导航隔离，会话操作和完整登录初始化不可因切页丢弃状态。结构分为 domain、secret、storage、service、httpapi 与 cmd/hub。前端位于 web。

配置是完整版本快照，草稿不能直接影响已发布内容。个人订阅相互隔离；共享模板变更通过预览和显式发布应用。密文绑定记录/字段上下文；令牌保留鉴权摘要并加密保存可恢复副本（AAD 绑定订阅 ID），普通列表不返回令牌或密文；管理登录使用密码哈希、会话 Cookie、CSRF 和限流；首次创建与修改管理员密码均至少 8 位。

## 部署

Compose 使用外部网络 wk、独立 data/secrets 命名卷，environment 仅设置 TZ=Asia/Shanghai；运行用户非 root，单进程单实例。宿主机 8097 映射容器内部 8097/TCP，首次启动自动生成随机主密钥和一次性码，通过引导创建管理员。后台不设地址白名单，不自动启用 HSTS；不以 Origin/Host 或 Sec-Fetch-Site 限制访问，管理写操作保留有效会话与 CSRF Token 校验，初始化保留一次性码校验。HTTPS Cookie 判断独立于授权，不增加 CORS 放行配置；具体规则见部署文档。已有库缺少原密钥必须拒绝启动。订阅地址由浏览器当前 URL 生成，Android 仍要求 HTTPS。

Actions 的 PR 只检查测试；master push 或手动触发在检查通过后推送 jiuwusan/z-jellyfin-hub 镜像，包含 latest 与提交 SHA 标识。需要仓库 secret DOCKERHUB_TOKEN。不增加远程 SSH 部署。

## 验证与提交

使用临时数据库和临时密钥进行测试，禁止测试依赖个人服务。前端类型检查与构建、go test ./...、go vet ./... 必须通过。当前分支工作，不自动提交或推送；提交格式为类型加中文摘要。

跨项目协议样例、需求和交接文件保留相对引用，复制后核对数量及 SHA-256。Android 实施订阅接入，iOS 仅归档交接，不宣称已实现。
