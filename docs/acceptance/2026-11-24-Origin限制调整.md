# Origin 限制调整验收

## 范围与实现

用户确认移除 Hub 的 Origin 限制，不修改现有 Nginx。初始化、登录与管理写操作不再校验 Origin/Host 或 Sec-Fetch-Site。初始化码、密码哈希、限流、管理会话和写操作 CSRF Token 校验保留；未增加 CORS 放行配置。

Cookie 判断与授权解耦，直连 TLS 优先；内部 HTTP 转发时合法 HTTP(S) Origin 仅提示 Cookie 协议，不匹配 Host。无有效 Origin 时，已有 HTTPS Cookie 用于保持 Secure 属性并清理退出/改密；否则使用 HTTP Cookie。HttpOnly、SameSite=Strict、Path=/、无 Domain 与 HTTP/HTTPS 独立名称不变。不增加转发头信任，无法识别无 Origin、无既有 Secure Cookie 的反代首次 HTTPS 登录，此时使用 HTTP Cookie。正常浏览器登录请求带 Origin。

## 验证

- 修改前新增回归失败：被改写的 Host 登录返回 403；合法会话/CSRF 因 Origin 或跨站标头被拒绝；HTTPS Cookie 与无 Origin 退出判断不符合目标行为。
- 修改后 `go test ./... -count=1`、`go vet ./...` 通过；前端 9 项测试、类型检查与生产构建通过。
- 临时真实 TLS 终止反代使用 Go httptest，无 X-Forwarded-Host/Proto，改写上游 Host；验证公网式 HTTPS 登录、读会话、内网 HTTP 独立 Cookie、错误 CSRF 拒绝、无 Origin 退出及改密后会话失效，Cookie 属性与清理均通过。
- 任意地址（域名、IPv4、IPv6）、缺失/不同/null Origin、跨站标头下合法会话和 CSRF 可写；错误密码、缺失会话、缺失或错误 CSRF 仍拒绝。初始化码错误拒绝、缺失 Origin 可初始化、禁止重复初始化。
- 检查 Compose、Dockerfile、Actions 构建路径，配置未改变；本机没有 Docker，未执行 Docker Compose 命令或镜像构建，不宣称生产部署通过。

测试使用临时数据库、随机密码和回环监听，由测试关闭并清理。没有使用真实账号或修改现有 NAS/Nginx/Jellyfin；未提交、推送、发布镜像或更新容器。此前验收文档中的 Origin 拒绝规则为当时行为，当前以本文与部署文档为准。
