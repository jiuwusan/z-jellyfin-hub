# 可选代理与直连验收

## 实现范围

Hub/Web 增加不使用代理的订阅选择，发布时省略 connection.proxy 并要求 Android 构建号至少 72；已有代理快照的最低版本保持原规则。Android 0.6.58（72）支持缺失/null 代理的显式直连，设置页显示连接方式；图片、HLS、字幕与 API 复用同一网络客户端，无代理认证泄漏，不按错误自动降级。iOS 本轮仅交接归档，无运行代码变更。

## 验证结果

| 范围 | 结果 |
| --- | --- |
| Go 完整测试、vet、嵌入前端的本机构建 | 通过 |
| Web 测试、TypeScript 检查、Vite 构建 | 12 项测试及构建通过 |
| Android Debug / AndroidTest 构建 | 通过，覆盖安装荣耀 |
| Android 受控路由检查 | 缺失/null、非法对象、版本门槛、缓存序列化、系统 HTTP 代理旁路、API/图片/HLS/字幕路由及代理模式保留通过 |
| 既有订阅 controller / lifecycle | 候选验证、304、不兼容配置、离线缓存、播放准备中延迟切换通过 |
| 荣耀原系统用户真实 HTTPS 直连 | 登录、首页、图片、HLS 播放、拖动和退出返回通过；原账号及保存的订阅未变 |
| 视频与解码 | H.264 1920×804，c2.qti.avc.decoder |
| 真实请求路由 | 11 次 API、4 次图片、2 次 HLS 清单和 3 次媒体请求均为 DIRECT，无 Proxy-Authorization |

先在旧 Hub 复现无代理订阅被拒绝，在旧 Android 复现无代理配置无法解析；实现后通过。独立只读审查未发现实质性问题。验收期间荣耀曾处于另一系统用户，该用户没有订阅；按用户确认切回原用户后完成真实验证。没有修改 Jellyfin、mihomo、Nginx 或线上 Hub 配置。

## 交付与限制

- 代码提交推送按用户后续确认执行，线上服务尚未部署。线上 Hub 仍需更新后，在订阅选择不使用代理，并绑定手机可达的 Jellyfin 地址，再显式发布；测试没有覆盖原订阅。
- 已卸载本轮测试包，移除另一系统用户下本轮创建的两份受控订阅测试存储；荣耀保持原用户并重新打开主应用。
- Compose 和 Dockerfile 未变，端口 8097、外部网络 wk、前端嵌入路径均核对；本机无 Docker 命令，未执行容器镜像构建或部署。
- 共享归档核验见 Player 的 [归档记录](../../../z-jellyfin-player/docs/requirements/Hub直连模式归档核验.md)，共 5 组 SHA-256 一致，29 个本地引用核对通过。
