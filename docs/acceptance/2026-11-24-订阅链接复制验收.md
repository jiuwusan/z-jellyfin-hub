# 订阅链接持续复制

本轮仅 Hub 实施，未修改 Android/iOS 客户端、NAS 服务或其他服务配置；未发布镜像、未部署。

## 行为

详情页常驻“复制订阅链接”。新建、设置和轮换令牌同时原子保存鉴权摘要与 AES-GCM 密文；密文使用既有主密钥及绑定订阅 ID 的 AAD。复制是独立的管理员会话和 CSRF 保护操作，响应禁止缓存；普通列表仅返回 `hasSavedToken`，不返回摘要、令牌或密文。

旧数据库自动增加可空密文列，原摘要和设备鉴权不变。旧订阅点击复制时引导补录原链接或原令牌，后台验证摘要匹配后保存密文；失败不改变链接，成功不轮换、不增加配置版本、不改变已发布快照。页面刷新后可再次复制，不必重复补录。复制地址继续从当前后台物理目录生成，保留 Nginx 子目录，后台 hash 不进入订阅地址。从 HTTP 后台复制时保留 Android 要求 HTTPS 的提示。

## 验证

| 范围 | 结果 |
| --- | --- |
| Go 完整测试、`go vet ./...` | 通过 |
| 前端 `npm test` | 11 个检查通过，含原链接解析、路径前缀、Clipboard API/HTTP 回退及失败清理 |
| 前端类型检查和生产构建 | 通过，产物进入 Go embed 对应目录 |
| 数据存储 | 旧结构迁移、重启及备份恢复通过；数据库/WAL/备份不含明文令牌；密文篡改及跨订阅替换被拒绝 |
| 服务与管理 API | 手动/随机令牌保存、草稿编辑保留、轮换旧令牌失效、补录匹配及错误拒绝通过；未登录/缺 CSRF 不可复制或补录，响应 no-store |
| 配置稳定性 | 补录前后已发布配置指纹与版本一致，原设备令牌仍可鉴权 |
| 隔离浏览器联调 | 使用随机临时密钥、账号和令牌在任意子目录下验证新订阅复制、旧订阅补录后复制、刷新后再次复制；复制失败显示手动弹窗，导航后清除临时链接 |
| Compose / Dockerfile | 静态核对外部 wk、8097 映射、前端产物及 Go embed 构建路径；本机无 Docker CLI，未执行镜像构建及 Compose 启动 |

浏览器联调拦截剪贴板写入，仅在隔离页面内比较随机测试值，未覆盖使用者实际剪贴板。临时服务、测试页、数据库及探查程序在验收后清理，不保留实际订阅链接截图或凭据。线上需后续发布部署才出现新按钮。
